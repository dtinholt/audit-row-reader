# Changelog

## 0.1.0, 11 October 2026: first public release

The build as it stood after the second independent check, published under Apache-2.0 with a README for outside readers, a CI workflow and a single screenshot. The internal experiment-page notes, the palette validator output and the full screenshot set stayed behind.

## 2026-10-10 · second independent check, eight fixes

1. A top-level field named `constructor`, `toString`, `valueOf` or `hasOwnProperty` made the redaction scan look up `Object.prototype` and throw on load. Field lookups now use `Object.hasOwn` and Maps. Self-check: such a row loads and each field is counted.
2. The field and per-field match counts were plain objects, so a `__proto__` key could reach `Object.prototype`. They are Maps now, and sanitised JSONL builds rows on a null-prototype object. Self-checks: `({}).email` stays undefined after loading the row, `__proto__` shows in the export field picker, and a ticked `__proto__` field survives the JSONL export.
3. A phone number in the same text as a valid IBAN went uncounted. Only the matched IBAN span is now blanked before the phone pass. Self-check: both count, and an IBAN alone does not count as a phone.
4. With one log and one seal left, the page applied the seal even when its `# file:` line or its own name pointed at another file. It now refuses and says which file the seal names. The sample log is now called `sample-audit.jsonl` so its seal pairs by name. Self-checks: core and page.
5. A seal with upper-case hex or CRLF endings read as zero hashes, and the verdict then treated every row as appended. Case and line endings are normalised. A seal with no readable hash lines now reports "the seal could not be read" and gives no verdict, in the page and in `seal.py`. Self-checks and three Python tests.
6. Loading the same file twice doubled every row. Duplicates are found by an FNV pass over the lines, confirmed line by line, read once, and reported with their SHA-256. Self-checks: core and page.
7. Layout: the drift chart's end labels ran 2 px past the content edge at 1280. The right margin grew, the calibration-change label flips left near the edge, and a self-check measures every label and end mark at full width and at 358 px. The trail's Answer column has a minimum width and the scroll cue shows at every width.
8. `sample/sample-audit.jsonl.chain` is regenerated by the current `seal.py` with its `# start:` and `# file:` lines. The corrupted copy and `sample.js` were regenerated with it. Python test: the sample seal is v2 and matches.

Counts after this round: 51 core self-checks, 84 with `?selfcheck`; 62 Python tests under `-W error`.

## 2026-10-10 · stress, review, elevate

### What broke under stress

Inputs came from `tools/make_stress.py`: an empty file, `tests/fixtures/hostile.jsonl` (script and img payloads in every text field and in option names, right-to-left and combining unicode, CRLF mixed with LF and a bare CR, a duplicated request id across six timestamps, P(yes) of -0.3, 1.7, 1e308 and 1e400, a string "0.5", NaN, 5,000-deep arrays, 3,000-deep objects, a BOM row, `null`, `[]`, dates on both DST changes and across the year boundary, an out-of-range year), the sample repeated 10x and 100x, 100,000 rows, and a 5 MB paste.

- Nothing executed. Every payload rendered as text in the old page and still does; the page check now asserts it with `window.__pwned`, an img count and a script count.
- An empty file said "Every line parses". It now says the log is empty and hides the other sections.
- Probabilities outside 0 to 1 went into the histograms clamped to the end bins, and 1e400 (read as Infinity) did the same. They now show as "out of range", stay out of the charts and get their own flag.
- A request id reused at six different times went unnoticed. It now has a flag.
- A bare carriage return silently joined two rows. The split rule stays the same as `seal.py` so seals still match, and the page now reports the count.
- Rows with no reading (null, a string, out of range) formed an "identical run" with each other. They no longer count.
- The 100x log (46,100 rows, 40 MB) rendered in 363 ms but froze the tab for that time, drew every point of the drift line, and the trail paged 100 rows at a time. With a seal it would have added about 300 ms more inside the same frozen stretch.
- A 40 MB paste left in the textarea made every redraw slow: reading it took 4.8 s against 0.5 s for the same text without the box. Pastes over 1 MB now leave the box once read, with a note to drop the file instead.

### What the hostile review found

- A load that was stopped or overtaken by a newer one could leave the page state half-replaced (rows from one log, flags from another). Hashing now runs on a staging object and the page state changes in one step at the end. Page check: two loads started back to back.
- An export warning left open across a new load would have exported the new log under the old counts. A load now closes it.
- `setTimeout` yields are clamped to one second in background tabs, so a big load in a hidden tab crawled. Yields now use a message channel.
- The row-height measurement in the virtual table could recurse without end if a row's height kept changing. It now measures once per draw.
- In-band rows in the calibration table were marked by shading alone. They now carry a "band" tag.
- Opening a row redrew the table and dropped keyboard focus. Focus now returns to the same row button.
- `localStorage` access can throw (blocked storage, private windows, quota). Every read and write is wrapped, the page says when settings were not saved, and defaults apply.
- The case view first used oxide red for changed answers. The lab identity allows that colour once, for breaks, so changed answers are now ink with a heavy underline and a "changed" label.
- Two silent catches got a comment saying why they are safe to ignore. Load errors were never silent: they log to the console and show under the paste box.
- Long option names stretched the chart and trail selects past the page width on phones. Selects are capped.
- No console errors on load, checked over the DevTools protocol in `tests/cdp.mjs`.

### Added

1. Large logs: streamed file reading with a progress bar and a Stop button, a virtual trail table that draws only the rows in view, a go-to-row box, prefix sums and down-sampling in the drift chart, and read, hash and draw timings under the file list.
2. Multi-file sessions: several logs and seals at once, ordered by first timestamp, seals paired by name, by `# file:` line or by first hash. Seal chains and `prev_hash` chains verify across files, and every boundary is reported. Seal format v2 adds `# start:` and `# file:` lines; v1 seals still read.
3. Calibration by question: for yes/no questions, a bin table per calibration document (rows, share, mean P(yes), mean raw P(yes), share answered Yes, share flagged) and a before and after line for each change, with the note that the log holds no outcomes.
4. Cases: rows grouped by `request_hash`, each case's requests in time order with the gap since the previous one, and a flag when one question got different answers inside a case. The sample now holds three re-asked cases sent after the calibration change.
5. Saved screens: band bounds, run length, run key, the KS line and the answer-mix line persist in `localStorage`, with a reset.
6. Redaction check: counts of email, phone, checksum-valid IBAN and name-like matches across every text value and key, per field. Exports stop behind a warning when a match would leave the page.
7. Exports: the flagged list as CSV (with spreadsheet-formula cells neutralised) and the whole trail as sanitised JSONL with the fields you tick.
8. A "Keeping the seal" guide quoting the decision-head security review.
9. `tools/seal.py`: `rotate`, `verify-series`, `seal --after` and `--start`, and `--json` on every command.
10. Self-checks for every feature, including a corrupted series that breaks at the right boundary in four ways.
